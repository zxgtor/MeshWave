# Mesh Wave 使用指南

安装与启动请先阅读 [项目首页](../README.md)。

本机运行的模型包裹原型：OBJ 导入 → 对应点 → 非刚性贴合 → OBJ 导出。

默认界面采用 Graphite Studio：石墨灰工作区、钢蓝交互强调色、深浅冷灰模型和银灰 Mesh Wave Logo。界面主题位于 `web/studio.css`；纹理、权重热图和网格诊断的功能色继续按各自含义显示。

按项目首页安装依赖后，Windows 用户可双击 `start.cmd`，浏览器会打开 <http://127.0.0.1:6188/>。仓库已包含 `web/vendor/` 前端资源，运行时无需 CDN。

## 操作

1. 导入模板和目标 OBJ。模板上限 100,000 顶点（超过 25,000 顶点需多阶段模式），目标上限 200,000 顶点、500,000 三角面；单文件 18 MB。模型需要有效的多边形面。
2. 可先将两侧人脸调到正面，点击“自动识别人脸点”，检查 A 编号建议后点击“采用建议 · 替换点对”；也可按住 Shift 点击左侧模板的一个部位，再 Shift 点击右侧目标的相同部位。点会吸附到点击三角形最近的顶点。手动至少 3 对不共线的点，建议覆盖额头、眼角、鼻、嘴角、下巴等区域。
3. 点击“开始非刚性贴合”。先根据对应点做相似变换对齐，再进行带硬对应点约束的拉普拉斯非刚性 ICP。
4. 旋转视图、切换线框或叠加目标检查结果，再导出 OBJ。结果保持模板的顶点顺序、原始多边形与 UV；法线引用会移除以避免沿用变形前法线，导入建模软件后重算法线。单独导出 OBJ 保留原材质引用；烘焙后可用“导出纹理模型 · ZIP”获取新的完整材质包。

可先点击“载入演示”，它包含独立生成的模型、UV、扫描棋盘贴图和 7 对预设对应点，不使用原软件的模型资产。恢复原始模板会保留对应点和排除区域；替换任何模型会清空点对和结果，并清空被替换一侧的排除区域。

## 工程保存与恢复

顶部“保存工程”会下载一个 `.facewrap.json` 文件，内含两侧原始 OBJ、导入的单张贴图、对应点、成对曲线、笔刷影响权重、待配对的模板点、排除面、求解及烘焙参数、当前贴合结果和已烘焙贴图。即使只导入一个模型，也可以保存未完成工程。打开工程无需重新定位 OBJ 或重新选择已导入的图片；不包含未导入的外部 MTL、额外材质或其他纹理。

刷新后点击“打开工程”选择此前保存的文件，即可继续编辑；已保存的结果可直接导出。当前工程版本为 1，为容纳内嵌图片，工程文件上限提高为 96 MB。无效或不支持的文件会被拒绝，保留当前工作。存在未保存更改时，刷新/关闭页面或打开其他工程会提示确认。工程不会自动保存，请定期点击保存。

## 纹理显示与转移

1. 两侧 OBJ 均须包含完整的 `vt` 和面角 UV 索引。支持 UV 接缝和负索引；无需先导入 MTL。每个模型只使用一张 PNG/JPEG 颜色贴图，手动在“纹理与烘焙”中选择。模板贴图仅用于预览，可省略；扫描贴图是烘焙所必需的。
2. 顶部“纹理”控制显示/隐藏，“原色”去除视图灯光对贴图颜色的影响；取消“原色”可检查有灯光的表面。无贴图时仍显示原来的双色材质。
3. 完成模型贴合后，设置输出 256/512/1024/2048，边缘扩展 0–16 像素，最大投射距离为目标包围盒对角线的 0.1%–20%（默认 2%）。烘焙沿用贴合中的法线夹角。
4. 点击“烘焙扫描纹理到模板 UV”：按模板 UV 像素中心插值贴合后的三维位置和法线，查找目标保留面中朝向合格的最近点，再按其面角 UV 对扫描图做双线性颜色采样。显示烘焙贴图、有效 UV 像素覆盖率和未匹配数量。
5. “导出贴图 · PNG”下载模板 UV 的 RGBA 图。“导出纹理模型 · ZIP”包含 `model.obj`、`model.mtl`、`texture.png` 和 `opacity.png`，解压后放在同一目录。新材质统一引用烘焙颜色与透明度；不复制旧模型中的多材质配置。

限制与约定：

- 输入图上限 8 MB、16 百万像素；JPEG/PNG 统一解码为 RGBA PNG，PNG 规范化后仍需 ≤8 MB。图片按 sRGB 颜色使用，不进行 ICC 色彩管理；不烘焙视图灯光、法线、粗糙度或金属度。
- 模板 UV 需位于单张 0–1 空间，并在输出分辨率上无重叠内部像素；不支持 UDIM。零面积 UV 面会跳过并计数。扫描 UV 可重复，预览和采样均采用 repeat 寻址；OBJ 的 v=0 对应图片底部。
- 颜色在线性颜色空间以预乘透明度进行双线性插值，再编码回 sRGB。输入和烘焙图的预览使用同样的 UV 寻址，但低输出分辨率仍会损失细节。
- 模板排除面不烘焙；目标排除面不参与查询。超过投射距离、没有合格法线或未覆盖的区域保持透明，不伪造颜色。边缘扩展仅向 UV 岛外生长，不填补岛内的未匹配像素或排除区。
- 覆盖率的分母为未排除模板面的已栅格化 UV 像素，不包含 UV 岛外留白；它不代表整张图片不透明或所有几何面都有 UV 面积。
- 该流程依赖贴合质量，没有自动展开 UV、笼罩投射或遮挡消除；需在脸部开口、薄片等部位检查颜色串入。高分辨率和复杂网格可能耗时数分钟，尚未验证全部输入上限组合的性能。
- 改变图片或烘焙参数会清除旧烘焙图，保留贴合几何；重新贴合、恢复模板或编辑点对/区域会使几何结果及其贴图一起失效。

## 点对编辑

点对列表中，点击某一对的“模板 #…”或“目标 #…”按钮，再 Shift 点击相应视图，即可只替换这一侧的点。“取消重选”保留原点对；右侧“删”删除指定点对。重复顶点和排除区域中的顶点不可选用。开始编辑会恢复原始模板、清除旧贴合结果，需要重新计算。

## 自动人脸对应点

1. 导入两侧人头网格，放大脸部并将两侧视角转到正面，保持头部竖直；如果已有贴合结果，先“恢复原始模板”。有未完成点对或正在重选点时，先完成或取消编辑。
2. 点击“自动识别人脸点”。程序在后台生成两张 640×640 的灰模渲染图，不包含标记或排除区覆盖层，无需贴图和 UV，也不会修改当前显示材质。MediaPipe 在本机 CPU 上检测；截图不上传到外部服务。
3. 从检测结果中选择 18 个候选：鼻尖、鼻根、眼内外角、眉部、鼻翼、嘴角、唇中点、下巴和额头。将二维位置按实际渲染相机射线映射回原始 OBJ 的最近可见三角面，再吸附到该面顶点；不把神经网络输出的推测深度当成模型坐标。
4. 排除区、未命中表面、重复顶点和屏幕吸附误差大于图像宽度 2.5% 的点会跳过，两侧按相同特征编号配对。至少保留 6 对且两侧均不共线才显示建议，否则说明原因并保留原点对。
5. 预览以青色 A 编号显示建议，原点对仍在列表中。点击“采用建议 · 替换点对”才替换原点对；“取消建议”不改变原工作。预览未采用时不能开始贴合。采用后可逐点重选、删除，保存工程后作为普通点对恢复。

检测仍需人工检查：该模型主要用于二维人脸图像，在灰模、遮挡、闭眼、夸张表情、低面数或不同拓扑上可能漏检或吸附到不合适的位置。这里只做正面建议点，不自动猜测模型轴向、处理侧脸或进行原生三维语义分割；图像中没有唯一人脸、脸部太小或偏转较大时会拒绝检测。左右名称以人物自身为准，画面不可镜像。已有的防翻面检查仍会拒绝不合理对应点。

未采用的建议不保存，编辑模型、点对或区域后旧建议失效。原有棋盘椭球演示缺少完整人脸细节，不是人脸检测精度的测试样本；检测失败时继续使用手动选点。

MediaPipe 0.10.35 由 `requirements.txt` 安装，仓库已包含官方人脸模型；若 `models/face_landmarker.task` 缺失，运行 `python setup_landmarks.py` 下载并校验约 3.76 MB 的官方模型。只有这个显式安装步骤使用网络，检测过程不下载。模型来源和固定哈希见 `models/README.md`，API 参考：[MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)。

## 曲线对应约束

在“选择对应点”下点击“新增成对曲线”，给曲线命名，例如上眼睑、上唇线、鼻翼。按住 Shift，在模板和目标的相同部位依次点击控制节点；系统吸附到点击三角面的顶点，并沿网格边的最短路径连接。两侧控制节点数量可以不同，但起点、经过的部位和方向应对应。青色“起”和数字标记控制顺序，可撤销任一侧最后节点并重新选点，或反转右侧方向。闭合曲线请勾选闭合，不要重复点击起点。

点击“生成对应点预览”，按两侧各自的表面路径弧长采样并吸附到顶点，S 编号显示新增点；确认后点击“采用曲线点”才进入现有点对列表，参与单阶段/多阶段求解及笔刷硬锁定。曲线折线本身不是独立的连续约束，也不是平滑样条或三角面重心坐标约束；粗网格的小区域应减少采样数。仍需至少 3 对整体不共线的对应点，建议先用分散的人脸点完成整体定位，再用曲线细化局部。

- 支持最多 12 对命名曲线，每侧最多 32 个控制节点，每条曲线 2–30 对采样；开放曲线每侧至少 2 个节点，闭合曲线至少 3 个。所有普通点与曲线点合计最多 100 对。
- 路径不能跨越断开的网格、排除顶点或重复经过同一顶点。控制节点所在面不能被排除；其他排除区变化后，重新生成时会按当前可用网格检查路径。
- 同一映射的已有点及曲线共享端点会复用，因此新增点数可能小于采样数。吸附重复或顶点映射冲突会拒绝整个预览，不部分添加。不会自动猜测曲线方向；即使两侧方向错误，也可能没有索引冲突，需检查编号与部位，求解仍受防翻面约束。
- 修改或删除曲线后，旧点对保留到下一次生成并采用。重新采用会替换此前未手动修改的曲线生成点，保留普通点；手动重选后的曲线点按普通点处理，可能需要手动删除以解决新采样冲突。删除最后一条曲线后仍可生成空预览并采用，以移除旧曲线点。
- 工程保存曲线名称、控制节点顺序、采样数、闭合状态及已采用点的来源记录，也可保存未画完的曲线。预览建议不保存，打开工程时重新计算可用路径；旧工程缺失曲线字段时视为空。导入任一新模型会清空曲线和点对，恢复原始模板或重新求解会保留它们。已有结果时先恢复原始模板再编辑曲线。

## 区域排除

“点击操作”选择“排除区域”或“恢复区域”，再 Shift 点击任一模型。可选单个三角面或扩展周围 1/3 圈相邻面；红色显示排除范围。邻接范围按共享顶点扩展，不是屏幕上的圆形笔刷，可能包含曲面背后的相邻面。支持撤销上一次区域操作或清空两侧排除。

- **模板**：排除面涉及的全部顶点（含边界）在对应点整体对齐后固定，不参与局部非刚性变形；并非固定在导入时的世界坐标。
- **目标**：排除面不进入三角面最近点查询；与保留面共有的边界仍属于保留表面，可以参与匹配。
- 含对应点的面不能排除，不能排除全部目标面。修改已求解工程的区域前，请先点击“恢复原始模板”。恢复区域后新增对应点，若撤销区域操作会与新点冲突，该撤销会被拒绝。
- 恢复工程会保留排除区域，但不保留此前的区域撤销历史。

## 范围与限制

- 独立实现，非 Faceform Wrap 源码复原，也不调用原程序。REA 用于安装包结构与工作流调查；证据见 [REA 调查记录](rea-notes.md)。
- 目前只有 OBJ，不包含节点编辑器或动画；自动人脸点限正面灰模图像辅助检测，纹理限每模型一张颜色图。
- 适合形状接近的模板和目标；不同姿态、孔洞、遮挡、交叠或错误对应点仍可能导致不良贴合。已加入法线过滤与保守的局部防翻面，但没有全局自相交检测。
- 误差为未排除的模板顶点到目标保留三角面集合的单向平均欧氏距离，单位沿用目标模型。最近点可位于面内部、边或顶点，不再依赖表面采样。这不是双向距离或完整 Hausdorff 距离，也不能单凭误差判断视觉正确性。
- 当前网格上限是输入限制，不代表所有达到上限的模型都已验证性能。
- 预览与计算采用扇形三角化；非凸多边形请先在建模软件中三角化。
- 所有计算在本机进行，服务仅监听 `127.0.0.1:6188`。关闭浏览器不会停止后台 Python；需要停止时，可按命令行中的 `server.py` 找到对应进程再结束。

## 贴合质量控制

### 多阶段求解

新建工作默认“多阶段 · 从粗到细”，可切换“单阶段 · 对照”。旧工程未记录模式时恢复为单阶段，避免改变旧参数；可手动切换多阶段后重新保存。

- 粗配准与中层贴合按网格连通关系聚合自由顶点，构造平滑插值基，减少形变自由度和精确表面匹配查询。不同连通的薄片不会仅因空间位置接近而合用控制点；固定区域和硬对应点不进入自由变量。
- 早期每个聚合选一个代表顶点，并按聚合顶点数加权，近似原始网格的数据项；形状保持项投影到低自由度空间。各阶段继承上一阶段的完整形变。
- 最后一阶段使用所有自由顶点及全部未排除的匹配点，对完整目标保留三角面进行精确匹配。原始顶点顺序、多边形、UV、贴图工作流均保留；不输出简化网格，也不生成额外细分拓扑。
- 总迭代预算仍为 5–50，并非每层各执行该次数。三层通常分配约 25% / 30% / 45%，两层约 40% / 60%；小网格会跳过没有必要的粗层，极碎的拓扑可能无法充分聚合。
- 所有阶段都检查完整原网格的防翻面路径。粗层方向被阻挡时仍可尝试下一层，最终全顶点阶段无法安全推进时提前停止；不会为了进入下一层放宽保护。
- 结果表显示实际控制自由度、匹配点数、迭代次数、每阶段完整网格精确误差与耗时。粗层的逐次 `history` 使用当前阶段代表点与质量权重，不能跨层当作同一采样集合比较；阶段表和最终指标始终在同一完整未排除网格上计算。
- 模式随工程保存；恢复旧结果不自动重算阶段统计。不同网格、约束或迭代预算下，速度和误差改善程度不同，不能保证每次都优于单阶段。模板 100,000 是输入上限，不代表所有上限组合都已验证性能；最终精修仍需要全顶点稀疏求解。

分层聚合与平滑插值的背景参考：[PyAMG 聚合方法](https://pyamg.readthedocs.io/en/latest/generated/pyamg.aggregation.html)。这里是独立的 NumPy/SciPy 形变空间实现，没有新增 PyAMG 依赖，也不是调用它的 AMG 求解器。

- **精确表面匹配**：AABB 层次包围盒树按距离下界剪枝，查询连续三角面最近点。没有使用固定数量的近邻面替代全局搜索；计算精度受浮点数和 OBJ 三角化方式限制。目标零面积面被忽略，全部无效则报错；模板零面积或过小三角面需要先清理。
- **法线过滤**：每次迭代重算模板面积加权顶点法线，寻找夹角合格的最近目标面。默认最大夹角 60°，可设置 10–89°；越小越严格。两侧绕序需一致，整体法线大多相反或匹配不足时会提示错误，不自动猜测朝向。此处使用目标几何面法线，不依赖 OBJ 中旧的 `vn`。
- **防翻面**：相对于整体对齐后的模板，为每个三角面保留至少 1% 的有符号投影面积。检查整个线性更新路径，包括中途塌陷、终点恢复正面积的情况；危险步长会缩小，必要时提高平滑强度重新求解，再无法安全移动则提前停止并保留安全状态。硬对应点和固定区域仍精确满足；若初始化约束已不安全则报错。
- 该保护是保守的局部约束，会限制相对初始面法线接近或超过 90° 的大旋转，可能阻止部分合理的大幅变形；它不保证无远距离三角面穿插。界面显示实际/请求迭代次数、最近匹配过滤数量和防翻面调整次数；保护触发时，较低的迭代次数或较高残差是可能的。
- 误差指标使用不带法线限制的最近三角面距离，便于观察几何残差；求解匹配使用满足法线阈值的最近面。“法线过滤”计数是最终状态中几何最近面不满足角度阈值的顶点数量，不等于完全没有可用匹配的数量。
- 法线夹角随工程保存。旧工程缺少此参数时默认 60°，文件版本仍为 1。保存的旧结果不会自动重算或被认证安全；打开后会提示尚未验证，重新计算才应用新约束。重新计算失败后，旧结果会失效，避免误导性导出。

实现与背景参考：[libigl 最近点与 AABB 查询](https://libigl.github.io/tutorial/#closest-points)、[Open3D ICP](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html)。本项目使用独立的 NumPy/SciPy 实现，没有新增这两个库的运行依赖。

## 笔刷修正

完成贴合或恢复结果后，在“笔刷修正”选择外推、内压或局部平滑，在左侧结果上按住左键拖动。外推/内压沿当前顶点法线移动，平滑向邻接顶点均值移动。半径为目标包围盒对角线的 0.2%–20%，强度为 1–100；粗网格的小笔刷可能没有可移动顶点。

也可选择“表面投射”或“贴面平滑”：前者向扫描目标的最近合格三角面靠拢；后者先根据邻接顶点计算放松位置，再寻找目标表面。查询覆盖三角面内部和边界，使用本地 AABB 树加速，不依赖最近顶点或固定数量的候选面。目标排除面与零面积面不参与投射。

投射最大距离为当前笔刷半径，法线过滤沿用本次贴合的“法线夹角”。无合格目标时跳过该顶点，当前结果与目标法线朝向应一致。强度、边缘衰减、每步移动上限和防翻面会限制实际移动，因此一次笔画不保证精确落在目标表面，可持续涂抹逐渐靠近；贴面平滑也不保证曲面上的零残差。它不是沿法线射线投射；同向且相距很近的多层表面仍可能匹配到错误层，应减小半径并检查结果。

- Alt + 左键旋转，右键平移；Esc 或窗口失焦取消当前笔画。Ctrl/Cmd + Z 撤销，Ctrl/Cmd + Shift + Z 或 Ctrl + Y 重做，也可使用面板按钮。
- 对应点、模板排除面及其边界顶点锁定。按网格边距离限定范围，并过滤背向顶点，避免同时刷到空间相近但不连通的薄片；不保证遮挡后所有表面都被剔除。
- 每一步检查受影响的完整三角面及连续更新路径，沿用相对整体对齐模板至少 1% 投影面积的防翻面约束；危险步长会缩小或被拒绝。这不是全局自相交检测，平滑也可能造成局部收缩。
- 最多保留 20 笔、约 32 MB 坐标历史；超过限制会丢弃最早笔画。工程保存修正结果和半径/强度，重新打开后清空笔刷历史，回到浏览模式。顶点顺序、原始面和 UV 保留。
- 几何改变后，旧求解误差、阶段统计和烘焙贴图失效，需要重新烘焙。撤销/重做只恢复几何，不恢复旧烘焙；取消尚未提交的笔画会完整恢复该笔之前的状态。
- 打开旧工程不会自动认证结果安全；启用笔刷时验证防翻面与锁定点。如果旧结果不满足约束，请重新贴合。

### 软遮罩与权重绘制

在笔刷操作中选择“绘制影响权重”，设置“绘制值 %”，沿用笔刷半径与强度在左侧拖动。0% 表示完全保护，100% 表示完全影响；默认所有顶点为 100%。低强度和边缘衰减可逐渐形成过渡，“平滑权重”根据邻接顶点平滑遮罩，不改变几何。可用“全部保护”后局部绘制 100% 的方式，只开放需要修正的区域。

- 蓝色表示保护、金色表示可编辑、红色表示对应点或排除区的硬锁定；绘制时自动显示权重，可关闭“显示影响权重”恢复正常纹理预览。颜色只用于查看，不写入烘焙贴图或 OBJ。
- 权重同时影响外推、内压、局部平滑、表面投射和贴面平滑，在每步位移上限处理后相乘，再执行完整防翻面检查。硬锁定优先，不能通过绘制 100% 解锁。
- 绘制、平滑、全部保护/可编辑均进入同一逐笔撤销历史；可与几何笔画按操作顺序撤销/重做，Esc 取消当前笔画。单独修改权重不改变模型、求解统计或已有烘焙；实际修改几何后仍需重新烘焙。
- 权重按模板顶点顺序保存在工程的 `brushWeights` 中，旧工程缺少该字段时视为全部 100%。恢复原始模板、调整参数、重新贴合或替换目标时保留权重；导入新模板/演示时重置。权重控制手动笔刷和纹理细化，不改变普通几何贴合求解器；撤销历史仍不随工程保存。

## 网格诊断与清理

在“网格诊断与清理”选择模板或目标，点击“诊断原始模型”；也可用“检查待修复 OBJ 文件”检查普通导入会拒绝的损坏文件。独立诊断窗口支持旋转、缩放和平移，不替换当前工程。

- **红色**：超过两个有效去重三角面共享的非流形边，以及具有不连通面扇的非流形顶点。正常开放边界不算错误。
- **橙色**：无效面、重复面及无效 UV 引用的可定位部分。无效面包括错误/越界索引、引用非有限顶点、重复顶点和零面积或极接近共线的三角面。重复面按相同顶点索引集合判断，不按空间位置焊接。面积检查采用三角面自身边长尺度，避免远处孤立点把正常小面误判为退化。
- **青色**：未被有效去重三角面引用的有限坐标顶点，包括只被无效面引用的顶点。
- **紫色**：两个相邻面沿公共边使用相同方向的绕序冲突。不能定位的问题会列出原始 OBJ 行号，最多显示 100 条详细记录。

点击“生成修复预览”，会移除无效/重复三角面和孤立点，通过复制顶点分离多面共边、不连通顶点面扇及不可定向连接，并统一各面片内部绕序。有效三角面的空间位置保留，分离处可能形成开放边界和更多连通分量；不补洞、不焊接近邻顶点，也不检测或消除全局自相交，不自动判断整个连通分量应朝内还是朝外。预览会再次诊断，只有所列问题全部清零才提供可应用结果；清理后没有有效三角面或超过输出上限则拒绝。

预览后可在原始与修复结果间切换，或下载新的 `_repaired.obj`。原文件不会覆盖。输出统一三角化，保留有效面角 UV 和材质/分组声明，去掉旧法线引用；无效 UV 引用会移除并保留几何，可能不再具备完整 UV。下载 OBJ 不会复制外部 MTL 或图片。

“应用修复并清空约束”会替换所选侧，清空点对、曲线、排除区域和贴合/烘焙结果，避免旧索引错位。模板修复会重置软权重；目标修复保留模板权重。检查当前模型时，若完整 UV 仍保留，会保留该侧原始预览贴图；检查外部文件时不沿用旧模型贴图。

应用后可“撤销上次修复”，恢复修复前的模型、点对、曲线、排除区、软权重及结果/贴图。撤销仅在当前会话保留一次，开始其他编辑或打开新工程后失效，不恢复此前笔刷撤销历史；正常视图操作与保存工程不会使其失效。修复后的模型可照常保存工程，原始坏文件不能直接作为未修复模型存入工程。

输入沿用 18 MB、200,000 顶点、500,000 三角面的限制；修复后模板最多 100,000 顶点，目标最多 200,000。尚未认证达到上限时的诊断交互性能。

背景参考：[libigl 的非流形分离](https://libigl.github.io/dox/split__nonmanifold_8h.html)。这里采用独立的 Python 拓扑处理，没有新增 libigl 运行依赖。

## 纹理辅助贴合

适用于同一人物从中性表情到其他表情的局部细化。先完成几何贴合，在“纹理与烘焙”分别加载模板的中性表情贴图和目标表情扫描贴图，两侧均需完整 UV。UV 布局、网格顶点数量和拓扑不必相同，但模板颜色必须与该人物的皮肤特征对应。不能用当前目标刚烘焙到模板上的图证明匹配正确；本功能只读取两侧模型各自加载的贴图，忽略当前结果的烘焙图。

1. 将左侧朝向调到正面，选择“仅正面”或“正面及两侧”，点击“计算光流细化预览”。虚拟视图采用共用正交投影，以左侧相机朝向为参考，另外两侧绕上轴偏转 ±25°。取景自动覆盖两侧模型；左侧缩放和平移不会限定局部优化范围，可用 0% 软权重保护其他区域。
2. 默认最终分辨率 384、2 次迭代、强度 50、每步最大位移为目标包围盒对角线的 3%。可选分辨率 256/384/512、1–5 次迭代、1–100 强度及 0.1%–10% 每步位移上限。多次迭代先在 256 上粗化，再到所选分辨率；只有一次迭代时直接使用所选分辨率，不能继续改善时提前停止。
3. 左侧显示候选几何及模板原始纹理，面板显示归一化灰度残差、匹配顶点数和实际迭代数。旋转检查后“采用纹理细化”，或“取消预览”恢复原结果/贴图。预览期间保存工程仍保存原结果，不保存候选；输入编辑暂时禁用。
4. 采用后保留原始顶点顺序、面、UV、点对、曲线和软权重，清除旧几何统计、烘焙图及此前笔刷历史。请重新烘焙后再导出贴图；可以继续使用现有笔刷修正。

本机 CPU 实现会渲染纹理、可见三角面和深度，计算 OpenCV Farneback 双向光流；过滤缺少真实局部对比度的区域、透明区、边界/深度断层、前后向不一致、法线不合格及过远匹配。排除面和背向面仍参与遮挡，不会作为缺口透到后层。图像点通过目标可见三角面的重心坐标映射到三维，多视图匹配检查一致性后进入稀疏平滑增量求解，再受目标表面距离、硬锁定和连续路径防翻面约束。

对应点（包括已采用曲线点）、模板排除顶点、0% 软权重顶点保持输入结果的原位置；其他权重控制本次纹理细化的影响。未直接观察到的区域受平滑与零位移正则约束，仍可能小幅移动。每个候选步只有在重渲染后的灰度残差改善时才接受；固定评价区域的缺失像素会受惩罚，最终所选分辨率没有改善则不产生可采用结果。

残差为同一参考可见区域的归一化灰度差，截断到 80，数字不是毫米、像素位移或真实解剖准确率。大遮挡、嘴内新出现区域、强高光、不同光照、重复/弱纹理或不相似贴图仍可能误匹配；该方法不自动验证人物身份，也不能替代初始几何贴合。只有前方可见区域得到直接光流数据，不保证全头均匀精度或原版 Wrap 等价效果。

工程保存参数及 `textureRefined` 标记和结果坐标，旧工程自动使用默认参数。暂不保存灰度残差统计、虚拟视图或候选预览，恢复后不伪造旧统计。更换原始贴图会使旧纹理统计及烘焙失效，但保留几何；实际笔刷改动会使细化标记/统计失效，取消当前笔画则恢复。所有计算在本机，不上传图像，不需要 API Key 或额外模型下载。尚未验证输入上限模型的交互性能或真实人物跨表情扫描集。

实现参考：[OpenCV 稠密光流](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)；工作流背景：[Faceform OpticalFlowWrapping](https://docs.faceform.com/Wrap/Nodes/OpticalFlowWrapping/OpticalFlowWrapping.html)。本项目独立实现，不调用原版程序或复制其算法。

## 批处理与表情序列

在“批处理与序列”选择多个目标 OBJ，复用当前模板、迭代次数、平滑强度、法线夹角、单/多阶段模式及模板排除区，后台逐个执行几何贴合。默认使用原始模板；勾选“将当前贴合结果作为本批模板”可把已拟合的中性几何作为输入。开始时固定完整快照，每个扫描都从同一模板独立求解，不把前一帧形变累积到下一帧；当前工作区不会被批量结果替换。

两种约束模式：

- **同拓扑序列**：复用当前已采用点对（包括曲线生成点）和目标排除面。每项检查目标顶点数量和三角化后面索引顺序是否与当前参考目标一致，不一致则单项失败。编号仍须对应相同解剖部位；连接关系一致不能证明顶点编号的语义一致。
- **不同拓扑扫描**：先在单次流程里为各扫描建立并采用点对，点击“导出当前扫描约束 JSON”。批量加载这些 JSON，按扫描完整文件名匹配（忽略大小写），并核对模板拓扑指纹。也可把同模板文件的 `items` 合并到一个 JSON。每项使用自己的点对和目标排除面；模板排除区及求解参数仍来自本批快照，缺少或无效的该项约束会记录失败。JSON 顶点/面索引从 0 开始，界面 `#` 编号从 1 开始，建议使用导出按钮生成。

队列按文件名自然数字顺序执行，例如 `frame1`、`frame2`、`frame10`，同一批文件名不能重复。每批最多 50 项，单 OBJ 18 MB，上传文件合计 256 MB；输入沿用模板 100,000 顶点、目标 200,000 顶点/500,000 三角面限制。未压缩 OBJ 输出累计上限为 256 MB，超过时保留此前成功项，当前项失败、后续项跳过。只占用一个求解任务，单项失败后继续，不自动修复网格以免改变编号。

完成后自动生成 ZIP，可选择自动下载或手动“下载结果 ZIP”。包含几何项的 `results/序号_扫描名_wrapped.obj`、`report.json`、可用 Excel 打开的 UTF-8 `report.csv`、`settings.json` 和说明。输出保持所选模板的顶点顺序、原始面和 UV；旧法线引用按普通 OBJ 导出规则移除。仅几何项保留原材质引用，MTL/图片请使用模板配套文件。光流细化需显式勾选，不自动执行笔刷。

勾选“每项贴合后烘焙扫描纹理到模板 UV”，再多选各扫描的 PNG/JPEG。按文件主名匹配，忽略大小写，例如 `scan01.obj` 配 `scan01.png` 或 `scan01.jpg`；同主名多张图片会记录歧义，不猜测。每扫描一张颜色贴图，不解析 MTL 的多材质贴图，也不自动沿用当前工作区目标贴图。输入单图 ≤ 8 MB / 16 百万像素，模型加贴图累计 ≤ 256 MB。

批量烘焙使用第 06 节当前分辨率、边缘扩展、投射距离及当前法线夹角，开始时固定快照。每项先求解，再在贴合结果上将该扫描纹理投射到模板 UV，遵守本项模板/目标排除区。模板需完整、不重叠的单张 0–1 UV，扫描需完整 UV；沿用单次烘焙的透明像素、法线和距离过滤规则。

成功项位于 `results/序号_扫描名_wrapped/`，包含 `model.obj`、`model.mtl`、`texture.png`、`opacity.png`，解压后保持四文件相对位置即可使用。材质统一为烘焙材质，保留模板面和 UV 索引。JSON/CSV 报告包含烘焙状态、覆盖率和未匹配像素；覆盖率不足时透明区域仍需检查。缺图、坏图、缺 UV 或烘焙失败会将该项标为失败并保留已求解的几何，随后继续其他项；不会用其他扫描的图片代替。未压缩输出上限 256 MB 包含模型、材质、颜色与透明度贴图，超过后保留当前几何和此前结果、跳过剩余项。取消时等待当前项的求解及烘焙完成。

### 批量纹理辅助贴合

同一人物的表情序列可勾选“逐帧光流细化并自动烘焙”，每项执行 **几何贴合 → 光流细化 → 烘焙扫描纹理 → 带贴图导出**。选择扫描 OBJ 和同主名 PNG/JPEG 的方式不变，同拓扑序列或独立点对模式均可使用；顶点编号和人物身份仍需自行确认。

先在第 06 节给模板加载该人物的原始参考贴图，检查两侧完整 UV，左侧转到人脸正面，再设置第 08 节光流分辨率、视图数、迭代、强度和最大位移。开始时固定模板参考图片、当前左侧相机方向、软权重、光流及烘焙参数；不会拿某帧刚烘焙的纹理作下一帧参考。模板参考图计入 256 MB 上传限额，单图上限仍为 8 MB / 16 百万像素。每帧从同一模板独立完成几何/光流求解；需要降低跨帧抖动时，另勾选时序平滑。当前工程及撤销历史不被批量结果替换。

细化自动采用通过现有防翻面和残差改善检查的结果，保留硬点、模板排除区和 0% 权重保护，成功后在细化后的顶点上烘焙。JSON/CSV 另含 `flowStatus` / `flow_status`、细化前后灰度残差、匹配顶点数；`stats` 和 CSV 的 `mean_distance` 仍表示最初几何求解统计，细化几何统计见 `flowStats`。残差改善不保证真实解剖对应，遮挡、嘴内、光照差异和弱纹理需检查结果。

缺图、纯色/透明图、无可靠对应或没有可验证改善（包括已精确匹配的中性帧）会标记该帧光流失败，保留初始几何、跳过烘焙并继续下一帧；不会导出一个伪称“已细化”的带贴图成功项。光流成功但烘焙失败则保留已细化几何及光流统计。取消会等待当前帧的求解、光流、可选时序平滑和烘焙流程结束；服务中断时保留已确认的几何/带贴图结果，未完成阶段标为中断，不自动重算。模板参考图留在本机任务目录，ZIP 包含参数和参考图指纹，不额外打包输入参考图。

### 跨帧时序平滑

连续、等间隔的同一人物序列可勾选“跨帧时序平滑”。流程为 **几何贴合 → 可选光流 → 时序平滑 → 可选纹理烘焙 → 导出**；纯几何、批量烘焙、批量光流均可单独搭配。默认关闭，默认强度 35%、最大单帧修正为目标包围盒对角线的 1%，可设强度 1–90%、距离 0.1–5%。参数及模板软权重随批次固定，不写入工作工程。

保留两种时序模式。**单向**使用上一帧已平滑结果；**双向**先收集整段几何/光流结果，再使用当前帧相邻的未平滑前、后帧，各自按当前帧硬点的模板索引补偿姿态和尺度，平均后按强度混合局部形变。双向是半径一帧的中心对称滤波，不递归累计前后方向的结果，倒放顺序得到对称输出；能减少单向滤波的方向性滞后，仍可能削弱快速表情的峰值。候选位置仅向当前目标未排除、法线合格且在修正距离内的三角面投射，软权重调节实际位移，连续防翻面限步。当前帧硬点、模板固定区和 0% 权重顶点精确保留当前帧求解后的坐标。姿态补偿依赖点对分布，建议包含鼻梁/额头等稳定部位，避免只以剧烈运动的嘴唇作为姿态依据。

按文件名自然数字顺序处理，列表即时间顺序；不读取帧时间戳，数字有间隔的文件仍被当作相邻等间隔帧。单向首帧不改变几何，仅建立历史，失败后的下一成功帧重新建立历史。双向收集阶段的失败会切断片段，各片段首尾保持原几何，只有至少三帧的片段才有可平滑中间帧；最终平滑/烘焙失败后，后续帧不再把失败帧作为前邻帧，已经完成的邻帧不回算。片段切换、不同人物或不连续扫描请另建批次。较强单向平滑会造成快速表情滞后，双向也可能压低峰值；当前表面的法线噪声也可能因贴面投射而保留，不保证所有类型抖动均能消除。

每帧报告包含 `temporalStatus`（`seed` 为单向历史起点或双向片段边界）、`previousFrame`、双向的 `nextFrame`、`temporalStats`，CSV 追加状态、参考帧和平均/最大修正量；距离单位为 OBJ 模型单位。`flowStats` 中的光流残差表示时序平滑前的光流阶段，不是平滑后的纹理误差；烘焙始终使用最终时序顶点。单向只有整帧成功才进入下一帧历史；双向使用固定的原始几何缓存，避免循环读到已平滑结果。取消/中断后不自动延续历史到新批次。

勾选“自适应强度”可在单向或双向模式下按局部表情变化速度自动减弱平滑。默认关闭以保留现有行为；开启后，上方“平滑强度”变为最大强度。速度阈值默认 1，可设 0.1–10，单位为目标包围盒对角线百分比/相邻帧（不是每秒）；越低越早保护运动，越高越接近固定强度。

速度估计先用本帧点对补偿整体姿态/尺度，再对一圈网格邻域的位移向量取平均，减轻孤立顶点噪声的影响。单向用上一帧未平滑结果估计速度，并仍参考上一帧已平滑结果修正；双向分别计算前、后相邻未平滑结果到本帧的速度并取较大值，避免峰值两侧反向运动抵消成零。每个顶点的强度随速度连续降低，达到阈值时为 0，因此快速区域可保持当前帧峰值，慢速区域继续平滑。实际运动与大幅扫描噪声不能总是区分，低阈值也可能保留噪声；这不是表情语义识别或峰值全局保证。

硬点、固定区、0% 权重、目标排除面、修正上限和防翻面规则继续生效。首帧/双向片段边界、失败断开与取消语义不变，最终烘焙使用自适应后的顶点。`temporalStats` 增加 `adaptive`、`effectiveStrengthMean/Min/Max`、`speedMeanPercent`、`speedMaxPercent`及 `fastVertices`；强度统计针对未锁定顶点，在软权重/防翻面限步之前计算，不等于最终实际位移比例。JSON/CSV 及参数快照保留这些设置与摘要，不向工作工程写入批次参数。

双向收集阶段取消会停止接收后续帧，并完成已收集前缀的双向平滑/烘焙；前缀末帧作为新边界保留。双向平滑阶段取消则完成当前帧，其他已收集帧导出保留的原始几何并标记未平滑/未烘焙。服务中断也保留原始或已确认的最终几何，不能把 `prepared`（待双向处理）当作已完成。双向缓存位于任务目录 `inputs/*.temporal.npy`，受每批 50 帧/模板 100,000 顶点限制，额外磁盘上限约 120 MB（50×100,000×3×8 字节）；不打入 ZIP，未进行最大规模压力认证。

### 异常帧检测

时序平滑中可勾选“检测异常帧”，单向、双向均支持，默认关闭。启用后两种模式都先收集整段贴合/光流结果，再用不可变输入检查异常，最后对未隔离的片段执行所选平滑及烘焙；不会把可疑噪声直接视为自适应算法中的快速表情。共用上述缓存和两阶段取消语义，检测阶段取消保留已收集几何，未完成检测不会标成通过。

“异常偏差阈值”默认 2%，范围 0.1–20%，是几何偏差阈值，与自适应的速度阈值不同。检查三类信号：

- `scan_noise`：扫描顶点的一圈局部残差第 99 百分位，超过阈值，且相对同拓扑相邻扫描突增超过 3 倍加 0.01%。排除目标对应点、排除面及其邻近一圈、网格边界附近；尺度取扫描坐标 2%–98% 分位包围盒对角线，减少极端点改变尺度的影响。
- `surface_jump`：未锁定模板顶点到当前未排除目标三角面的最近距离第 95 百分位（最多均匀检查 2,048 顶点），超过阈值并显著高于相邻帧。排除硬点、模板固定区和 0% 权重，不以这些约束区域的离面距离判异常。
- `incoherent_jump`：对齐前后帧后，本帧局部偏差的高频残差过大、空间不连贯，且前后帧彼此相近，用于识别孤立贴合跳变。连贯表情速度高本身不会触发拒绝；不跨缺失的几何上下文判定此项。

比较证据先冻结，避免检测顺序改变结果；扫描粗糙度只与相同顶点数量及面索引指纹的相邻输入比较，不拿不同拓扑的统计强行对应。单帧/边界、缺少几何、受保护区域过多或不同拓扑时可能显示“上下文不足”，仍检查可用信号，不宣称一定正常。

未修复的可疑项计为失败并显示原因，保留已有贴合/光流几何、点对、区域约束及原扫描，跳过时序与烘焙，邻帧不再以它作平滑参考；检测本身不自动补帧、修改硬点或修复扫描；需要重建时可开启下文的异常帧修复。没有已有结果的求解失败项保留原输入。报告及 ZIP 包含隔离项已有 OBJ，JSON 的 `anomalyStatus` / `anomalyStats` 和 CSV 记录状态、原因代码、粗糙度、离面距离等证据。`clear` 表示未发现配置阈值下的异常信号，`limited` 表示上下文不足，另有 `rejected`、`failed`、`interrupted`、`skipped`，检测失败不会假装通过。

这是几何和时序启发式检查，不是表情语义识别：连续多帧异常、平滑但错误的切向对应可能漏检，剧烈而不连贯的真实动作或点对错误也可能误报。请复查可疑帧，必要时提高阈值或关闭检测另建批次重试；当前工程和原文件不被覆盖。

### 异常帧修复

勾选“修复异常帧并重新烘焙”会自动开启检测和批量烘焙，默认关闭。只修复已检测为 `rejected` 的帧；普通缺文件、损坏 OBJ、缺点对或未被识别为异常的求解失败项不会被擅自填补。每段连续异常必须有前、后两端可用正常几何，默认最多连续 3 帧，可设 1–5；序列首尾不外推，也不跨其他失败项寻找参考。端点须有原始几何缓存、有效质量统计且未被隔离；端点上下文可能为 `limited`，其状态写入修复报告供复查。

参考端点在修复前冻结，不递归使用已修复结果。先分别按本帧对应点补偿姿态和尺度，再按队列位置线性插值（沿用等间隔假设，不按文件名数字差或时间戳计算）。然后以当前帧硬点和模板固定区作精确约束，0% 权重保持本帧已有结果；缺少已有结果时使用按当前点对对齐的原始模板坐标。约束修正会平滑传播到其他顶点，冲突或翻面时拒绝采用。

重新贴合使用全顶点、带插值先验的非刚性求解：沿用当前迭代预算、形状保持、法线角度和时序最大修正距离，以插值为先验，只向附近且法线合格的扫描三角面贴合。自动排除不可靠扫描面，但不排除硬点所在面、不解除原区域约束；修复先验权重为 4，最大偏离受修正距离限制，持续执行防翻面检查。修复不重跑多阶段层级、光流或第二次时序平滑，以免重复追随损坏扫描；已修复帧也不作为其他帧的时序或插值参考。

修复后检查约束、可靠表面距离及跨帧几何连续性。原扫描被判噪声时，原始噪声判定保留：重新检查的是模板几何；可信扫描区域按距离检查，无可靠扫描覆盖的区域受插值先验和位移上限约束，不声称这些区域重新匹配到了有效扫描。`repairStats.qualityScope` 区分完整扫描和可信扫描/插值先验，保留 `fullScanFitQuality` 及自动排除面列表。无足够可信表面、缺正常端点、异常段过长、约束冲突或复检仍有几何异常时继续隔离。

合格几何重新从本帧扫描贴图烘焙，使用原目标排除面加修复过程中筛出的不可靠面。输出 OBJ/MTL/PNG；损坏区域无法可靠投射时为透明缺口，不伪造扫描纹理。几何修复成功但烘焙失败仍计该项失败，保留已修复 OBJ 及原因。插值仅为合理重建，不能保证恢复异常帧本来独有的表情峰值。

报告增加 `repairStatus`、`repairStats`、`repairError`、`repairOriginalError`，记录端点、插值比例、修复迭代、约束/防翻面、可信覆盖及重烘焙结果；成功几何的 `anomalyStatus` 为 `repaired`、`temporalStatus` 为 `repaired`，原 `anomalyStats` 与原光流统计仍指修复前证据。原扫描、已有异常 OBJ 和原 `.temporal.npy` 缓存在本机保留，原 OBJ 路径见 `repairStats.originalResultFile`；ZIP 导出修复后的当前结果，原始异常副本不重复打包。当前工程不被修改，原始输入不被覆盖。

修复期间取消会完成当前帧的修复和烘焙，再停止后续处理；中断时标记 `interrupted`，保留已确认几何，不自动恢复修复。输出仍受 256 MB 限额保护。未进行最大网格/最大异常段组合的性能认证。

“完成当前项后取消”不会强杀正在求解的项：当前项完成并保留结果，然后后续项跳过，仍可下载成功项和完整报告。上传阶段取消会把尚未上传的队列项也记录为跳过。打包阶段不可再取消。

任务输入、参数快照、结果和报告保存在本机 `output/batches/<任务编号>/`，原扫描文件不会覆盖。关闭或刷新页面后后台任务继续，重新打开同一浏览器可查询最近任务；任务跟踪不恢复未保存的工作工程，建议启动前保存工程。上传中断的草稿需取消后重新选择文件。本地 Python 服务停止则任务中断；服务重启后查询会标记未完成项，不自动恢复求解，并打包已确认成功的结果。完成任务可在服务重启后继续查询/下载。

“清空所选队列”清除页面选择和最近任务记录，不删除磁盘数据。批量输入/结果不嵌入 `.facewrap.json`，历史目录也不会自动清理；确认下载和备份后可自行清理相应任务目录。浏览器若拦截自动下载，可手动点击下载按钮。尚未验证最大批量和最大网格组合的性能。

## 开发

Python 3.10+（本机验证为 3.11），NumPy、SciPy、Pillow、MediaPipe、OpenCV（本机 4.13.0）。新电脑建议创建独立环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python server.py
```

重新获取前端依赖：`npm ci`，然后 `npm run vendor`。运行算法测试：`python -m unittest discover -s tests -v`；笔刷内核测试：`node --test tests/brush.test.mjs`。

Three.js 使用 MIT 许可，副本见 `web/vendor/THREE-LICENSE.txt`。数值库 API 参考：[SciPy 稀疏求解器](https://docs.scipy.org/doc/scipy/reference/sparse.linalg.html)、[cKDTree.query](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.cKDTree.query.html)。

图片与显示 API 参考：[Pillow Image](https://pillow.readthedocs.io/en/stable/reference/Image.html)、[Three.js Texture](https://threejs.org/docs/#api/en/textures/Texture)。
